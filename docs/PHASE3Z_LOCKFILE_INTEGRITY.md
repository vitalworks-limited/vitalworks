# Phase 3Z — Release lockfile integrity guard

The release preflight now checks each direct dependency and devDependency against both the root lockfile specification and its actual `node_modules/<package>` lockfile entry. Missing version, npm registry URL, or integrity metadata blocks release. This addresses a weakness where a fabricated root-only lockfile could pass the old preflight.

Regression fixtures were updated to resemble resolved npm package entries and a new test specifically rejects a superficial root-only lockfile. The fixture integrity value is test-only and **not** a real dependency lockfile.
